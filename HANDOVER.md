# BOLAKAY DIRECT: передача заказчику, новый домен, оплата

Состав проекта:

| Что | Где | Что хранит |
|---|---|---|
| Код | GitHub, репозиторий `bolakaydirect` | Сайт, функции ботов, миграции базы |
| Сайт | Render, сервис `bolakay-direct` | Запущенный сайт и его настройки |
| База и боты | Supabase, проект `bolakay-direct` | Заказы, товары, сотрудники, функции ботов и их токены |
| Боты | Telegram, @BotFather | `@BolakayDirectBot`, `@BolakayDirectShopBot` |
| Домен | Регистратор домена | Адрес сайта |

## Часть 1. Передача заказчику

Подходит и для передачи на другой свой аккаунт. Порядок важен.

### 1. Что заказчик готовит заранее

- Аккаунты на GitHub, Render и Supabase на своей почте. Для передачи ботов нужен ещё username в Telegram.
- Домен, оформленный на заказчика.
- Карта для платных тарифов. На бесплатном тарифе Render сайт засыпает, первое открытие занимает 30–60 секунд, поэтому для продаж нужен Starter (около $7 в месяц; проверьте цену на сайте Render).
- В Telegram у вас включена двухэтапная проверка. По неофициальным инструкциям она должна быть включена не меньше 7 дней, поэтому включите её заранее.

### 2. GitHub

1. Репозиторий → **Settings** → внизу **Danger Zone** → **Transfer ownership**.
2. Укажите аккаунт заказчика и подтвердите. Заказчик принимает передачу из письма.
3. История кода сохранится.

### 3. Supabase

Перенос проекта сохраняет базу, заказы, сотрудников, функции ботов и токены.

1. Заказчик создаёт организацию и приглашает вас: **Organization → Team → Invite**.
2. Проверьте условия: вы владелец текущей организации, вы участник новой, у проекта нет подключённой интеграции с GitHub и log drains.
3. На бесплатном тарифе в организации можно иметь только 2 бесплатных проекта. Если лимит занят, заказчик освобождает место или переходит на Pro.
4. Проект → **Project Settings → General → Transfer project** → выберите организацию заказчика.
5. Откройте сайт и проверьте, что точки и товары загружаются.

### 4. Render

Готовой передачи сервиса между аккаунтами я в документации не нашёл, на форуме Render пишут, что её нет. Если нужно, уточните в их поддержке. Простой путь: создать новый сервис у заказчика.

1. Заказчик входит в Render → **New → Blueprint** → подключает GitHub → выбирает репозиторий.
2. Вводит две переменные:
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: Supabase → **Project Settings → API Keys** → ключ `sb_publishable_...`;
   - `NEXT_PUBLIC_SITE_URL`: адрес сайта, пока временный `https://....onrender.com`.
3. **Apply**. Сборка занимает 3–6 минут.
4. Для продаж: **Settings → Instance Type → Starter**.
5. Старый сервис на вашем аккаунте удаляйте только в конце, после шага 8.

### 5. Домен

Раздел ниже: «Часть 2». Подключите его сейчас.

### 6. Боты

1. Сотрудник с ролью администратора открывает `https://новый-адрес/staff` → **Настройки**.
2. Нажимает **Обновить подключение бота** в разделе **Telegram-бот**.
3. Нажимает **Обновить подключение бота** в разделе **Бот для заказов**.

Передача самих ботов:

1. Заказчик пишет каждому боту `/start`.
2. Вы в @BotFather: `/mybots` → бот → **Bot Settings** → **Transfer Ownership** → **Choose recipient** → username заказчика → подтверждение паролем.
3. Если Telegram отказывает, значит двухэтапная проверка слишком новая или сессия недавняя. Подождите указанный срок.

### 7. Администратор заказчика

1. Supabase → **Authentication → Users → Add user** → email заказчика, пароль, *Auto Confirm User*.
2. **SQL Editor** → выполните, подставив email:

   ```sql
   insert into public.staff (user_id, full_name, role)
   select id, 'Имя заказчика', 'admin' from auth.users where email = 'email@заказчика';
   ```
3. Заказчик подключает свой чат: пишет боту `/admin`, нажимает «Войти как администратор» и входит (email, пароль, код из письма). Новые заказы начнут приходить ему. Посторонний без пароля и почты администратора чат не подключит.
4. Письма о смене пароля: подключите заказчику свой SMTP, см. раздел «Восстановление пароля» в `README.md`.

### 8. Завершение и безопасность

Выполняйте, когда заказчик проверил работу:

- [ ] Настройки → Сотрудники: отключите свой аккаунт.
- [ ] Supabase: выйдите из организации заказчика.
- [ ] GitHub: уберите себя из участников.
- [ ] Удалите старый сервис на своём Render.
- [ ] Заказчик в @BotFather делает `/revoke` для обоих ботов и вставляет новые токены в **Edge Functions → Secrets**: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_SHOP_BOT_TOKEN`. После этого снова нажимает обе кнопки из шага 6.
- [ ] Заказчик меняет секретный ключ Supabase, если вы его получали, и ключи Payme и Click, если вы их видели.
- [ ] Удалите у себя `.env.local` и файлы с паролями.
- [ ] Передайте заказчику лицензию на видео Vecteezy и права на фото. На сайте сейчас невидимая подпись Vecteezy: проверьте, позволяет ли это лицензия.
- [ ] Передайте заказчику этот файл и `README.md`.

### Если нужна новая база вместо переноса

Используйте, только если перенос Supabase невозможен, например нужен другой регион.

1. Создайте проект Supabase, регион лучше Frankfurt.
2. В `supabase/migrations/0006_telegram.sql` замените `hixmovjvfxrxtqittccz` на ref нового проекта. В `render.yaml` тоже.
3. Выполните файлы `supabase/migrations` по порядку номеров, от `0001` до `0017`. Файл `0013` выполняйте отдельно от `0014`.
4. Демо-товары: `supabase/seed.sql`. Настоящие заказы и товары: перенесите резервной копией через `pg_dump` и `pg_restore`.
5. Разверните функции:

   ```bash
   npx supabase functions deploy telegram-bot --no-verify-jwt --project-ref REF_ПРОЕКТА
   ```

   ```bash
   npx supabase functions deploy telegram-shop --no-verify-jwt --project-ref REF_ПРОЕКТА
   ```

   ```bash
   npx supabase functions deploy payments --no-verify-jwt --project-ref REF_ПРОЕКТА
   ```

   ```bash
   npx supabase functions deploy staff-code --no-verify-jwt --project-ref REF_ПРОЕКТА
   ```
6. Добавьте секреты токенов ботов и почты Brevo, настройте **Authentication → URL Configuration**, обновите переменные на Render, нажмите обе кнопки подключения ботов.

## Часть 2. Новый домен

1. Render → сервис → **Settings → Custom Domains → Add Custom Domain** → введите домен. Вместе с `www` добавится и основной адрес с перенаправлением.
2. У регистратора создайте **в точности те записи, которые покажет Render**. Удалите старые записи `AAAA`: Render они мешают.
3. На Render нажмите **Verify**. Записи могут применяться от нескольких минут до суток. SSL выпускается автоматически. Ошибка 502 сразу после проверки обычно проходит сама.
4. Render → **Environment** → `NEXT_PUBLIC_SITE_URL` = `https://новый-домен` → **Save** → дождитесь новой сборки.
5. Supabase → **Authentication → URL Configuration**:
   - **Site URL** = `https://новый-домен`;
   - **Redirect URLs** → добавьте `https://новый-домен/staff`.
6. Откройте `https://новый-домен/staff` → **Настройки** → нажмите кнопку подключения у **обоих** ботов. Так они получат новый адрес для ссылок и кнопки Web App.
7. **Распечатайте QR-коды заново**: `/staff` → **Точки и QR**. Старые QR ведут на старый адрес.
8. Проверьте: главная, витрина, заказ, кнопка Web App в боте, письмо о смене пароля.

Если старый адрес `onrender.com` уже напечатан или разослан, не отключайте его и не удаляйте сервис.

### Домен на vClouds

Записи создаются в шаге 2 общего списка выше. Значения для сервиса `bolakay-direct`:

| Type | Name | RDATA |
|---|---|---|
| `A` | `@` | `216.24.57.1` |
| `CNAME` | `www` | `bolakay-direct.onrender.com` |

Если Render показывает другие значения, используйте значения Render. Если сервис на новом аккаунте называется иначе, подставьте его адрес `onrender.com`.

**1. Проверьте Name-серверы.** Личный кабинет `https://m.vclouds.biz/clientarea.php` → **Домены → Мои домены** → домен → вкладка **Управление**.

Записи через **Manage DNS** работают, только если указаны `ns1.vclouds.uz` и `ns2.vclouds.uz`. Если указаны другие:

- сначала посмотрите, нет ли на домене почты: при смене серверов почта и старые записи могут перестать работать, их нужно перенести заранее;
- в меню справа откройте изменение Name-серверов → укажите `ns1.vclouds.uz` и `ns2.vclouds.uz` → **Изменить Name-севера**;
- смена занимает 12–24 часа.

**2. Добавьте записи.** Вкладка **Управление → Manage DNS** → **Add Record**:

1. **Type**: `A`, **Name**: `@`, **RDATA**: `216.24.57.1`, остальное не меняйте → **Add Record**.
2. Снова **Add Record**. **Type**: `CNAME`, **Name**: `www`, **RDATA**: `bolakay-direct.onrender.com` → **Add Record**.

**3. Удалите мешающие записи** в том же **Manage DNS**:

- все записи `AAAA` для `@` и `www`;
- другие записи `A` для `@`;
- запись `A` для `www`: вместе с `CNAME` она существовать не может.

Записи `MX` и `TXT` не трогайте: они нужны почте и проверкам домена.

**4. Проверьте.** Обновление занимает от 15 минут до часа, после смены Name-серверов до 24 часов. Введите домен на [dnschecker.org](https://dnschecker.org): для типа `A` должен быть только `216.24.57.1`. Затем нажмите **Verify** на Render и продолжайте с шага 4 общего списка.

**Если не получается:** сайт не открылся за сутки или в кабинете нет **Manage DNS** → поддержка vClouds: Telegram @vhelpdesk, +998 71 200 91 00, info@vclouds.uz. Спросите также, не заморожен ли домен. В статьях vClouds не сказано, нужна ли точка в конце значения `CNAME`: пишите без точки, а если панель откажет, уточните у поддержки.

## Секретный адрес панели

Панель персонала открывается по секретному адресу, а `/staff` отвечает «Страница не найдена». Это прячет вход от ботов, которые перебирают типовые адреса. Защищают панель по-прежнему пароль и код из письма.

**Как включить:**

1. Придумайте адрес из 12–64 латинских букв, цифр, `-` или `_`, например `panel-` и 16 случайных символов.
2. Render → сервис → **Environment** → добавьте `STAFF_PATH` = ваш адрес, без `/` → **Save** → дождитесь сборки.
3. Supabase → **Authentication → URL Configuration → Redirect URLs** → добавьте `https://bolakaygoatfarm.uz/ваш-адрес`. Без этого ссылка из письма о смене пароля не откроет панель.
4. Откройте `https://bolakaygoatfarm.uz/ваш-адрес`, добавьте в закладки и отправьте сотрудникам.

**Если адрес утёк:** смените `STAFF_PATH` на Render и адрес в **Redirect URLs**, разошлите сотрудникам новую ссылку.

**Если `STAFF_PATH` не задан или короче 12 символов,** панель работает по старому адресу `/staff`.

Везде ниже, где написано `/staff`, после включения используйте секретный адрес.

## Код из 6 цифр для сотрудников

Вход в `/staff`: email и пароль, затем код из письма на почту сотрудника.

- Код действует 10 минут, на него даётся 5 попыток.
- Повторно отправить письмо можно через минуту, всего не больше 8 писем в час.
- Подтверждение действует на одном устройстве 7 дней или до нажатия **Выйти**.

### Настройка почты

Письма отправляет Brevo. Ключ вставляете вы сами, никому его не пересылайте.

1. Зарегистрируйтесь на [brevo.com](https://www.brevo.com).
2. **Senders, Domains & Dedicated IPs → Senders → Add a sender**: укажите адрес отправителя и подтвердите его письмом.
3. **SMTP & API → API Keys → Generate a new API key**, скопируйте ключ.
4. Supabase → **Edge Functions → Secrets** → добавьте два секрета:
   - `BREVO_API_KEY`: ключ из шага 3;
   - `BREVO_SENDER_EMAIL`: адрес из шага 2.
5. Войдите в `/staff` как администратор и введите код из письма.

**Если письмо не пришло:** проверьте «Спам» и журнал отправок в Brevo. Если Brevo отклоняет запросы из-за неизвестного IP-адреса, отключите блокировку в разделе **Security → Authorized IPs**: адреса функций Supabase не постоянные.

**Чтобы письма реже попадали в спам:** подтвердите домен в Brevo и добавьте его записи `TXT` и `CNAME` через **Manage DNS** на vClouds. После этого смените `BREVO_SENDER_EMAIL` на адрес этого домена, например `no-reply@ваш-домен`.

### Когда код становится обязательным

Пока секретов нет, панель открывается по паролю и показывает администратору предупреждение. Когда активный администратор впервые введёт код из письма, база начнёт требовать его от всех сотрудников. Без подтверждённого кода сотрудник не получит доступа к данным, а администратор не сможет настраивать ботов и оплату.

### Если вход не работает

**Потерян доступ к почте сотрудника.** Supabase → **Authentication → Users** → сотрудник → смените email на рабочий адрес.

**Почта перестала отправляться и никто не может войти.** Supabase → **SQL Editor**:

```sql
update public.settings set staff_mfa_required = false where id = 1;
```

Затем удалите секрет `BREVO_API_KEY`: панель снова откроется по паролю. Исправьте почту, верните секрет, и требование включится при следующем вводе кода администратором.

### Передача заказчику

Заказчик заводит свой аккаунт Brevo и подставляет свои секреты `BREVO_API_KEY` и `BREVO_SENDER_EMAIL`. Коды приходят на email каждого сотрудника, поэтому от вашей почты вход не зависит.

## Часть 3. Payme и Click

### Как это работает

Оплата запрограммирована и развёрнута, но выключена, пока не добавлены ключи. Функция сервера: `payments`.

1. Покупатель выбирает Payme или Click, товар резервируется на 10 минут (меняется в **Настройках**).
2. Открывается форма оплаты. Пока покупатель платит, резерв продлевается до 20 минут.
3. Платёжная система подтверждает оплату на сервер. Заказ становится оплаченным только по этому подтверждению, а не по возврату покупателя на сайт.
4. Покупатель получает код на странице заказа и в боте. Администратору приходит сообщение в Telegram.

Договор, реквизиты и сверку денег ведёт заказчик. Кабинеты меняются, поэтому формальности уточняйте у менеджеров Payme и Click.

### Payme: подключение

1. Оформите договор с Payme Business как юрлицо или ИП.
2. В кабинете создайте **веб-кассу** с биллингом, протокол **Merchant API**.
3. Откройте `/staff` → **Настройки → Онлайн-оплата** и скопируйте адреса оттуда.
4. В настройках кассы укажите:
   - **Endpoint URL**: `https://<ref-проекта>.supabase.co/functions/v1/payments/payme`;
   - **Поле счёта**: `order_id`.
5. Добавьте секреты в Supabase → **Edge Functions → Secrets**:

| Секрет | Значение |
|---|---|
| `PAYME_MERCHANT_ID` | Merchant ID (ID веб-кассы) из параметров разработчика |
| `PAYME_TEST_KEY` | Ключ `TEST_KEY` для песочницы |
| `PAYME_KEY` | Боевой ключ `key` |
| `PAYME_TEST_MODE` | `1` на время тестов |

6. Пройдите оба сценария на https://test.paycom.uz: введите Merchant ID и `TEST_KEY`, в поле счёта укажите номер заказа, созданного с оплатой Payme, сумму в тийинах (сумма заказа × 100).
7. Для запуска **удалите** секрет `PAYME_TEST_MODE`. Панель показывает, какой режим включён.

### Click: подключение

1. Оформите договор с Click как поставщик услуг. Менеджер создаст сервис.
2. У сервиса в кабинете укажите:
   - **Prepare URL**: `https://<ref-проекта>.supabase.co/functions/v1/payments/click/prepare`;
   - **Complete URL**: `https://<ref-проекта>.supabase.co/functions/v1/payments/click/complete`.
3. Добавьте секреты: `CLICK_SERVICE_ID`, `CLICK_MERCHANT_ID`, `CLICK_SECRET_KEY`.
4. Спросите у менеджера, как сделать тестовый платёж. Отдельного тестового режима в коде нет.

### Включение на сайте

**Настройки → Онлайн-оплата → Включить на сайте.** Без ключей кнопка недоступна. Способ появится в оформлении заказа на сайте и в боте заказов.

### Правила для ключей

- Только в секреты Supabase. Не в Render, не в код, не в GitHub и не в переменные с началом `NEXT_PUBLIC_`: такие попадают в браузер.
- Не пересылайте ключи в мессенджерах. Если ключ попал в чужие руки, сразу запросите новый.

### Чек

Для фискального чека Payme заполните у каждого товара **ИКПУ**, **код упаковки** и **НДС** (`/staff` → **Товары**). Значения даст бухгалтер. Если у товара в заказе их нет, чек в Payme не передаётся. Уточните у менеджера, допустимо ли это по вашему договору.

### Возвраты и особые случаи

- **Деньги возвращаются вручную в кабинете Payme или Click.** Отмена оплаченного заказа в `/staff` снимает резерв и отмечает возврат, но денег сама не возвращает.
- Если вернуть деньги в кабинете Payme, заказ на сайте отменится сам. Выданный заказ так отменить нельзя.
- **Поздняя оплата Click:** если деньги списаны, а заказ уже снят, Click получает ответ «успешно», как требует их документация, а администратору приходит сообщение «Нужен возврат денег». Верните деньги в кабинете Click.
- **Поздняя оплата Payme:** платёж отклоняется, деньги не проводятся.

### Что не сделано

- Фискальный чек для **Click**: нужен отдельный доступ к их Merchant API. Уточните у менеджера и бухгалтера, требуется ли он.
- Автоматический возврат денег: только вручную в кабинете.

### Проверка перед запуском

1. Успешная оплата: заказ оплачен, код виден на странице, бот прислал сообщение, администратор получил уведомление.
2. Отмена на странице оплаты: заказ остаётся неоплаченным, кнопка «Оплатить» работает снова, через 10 минут резерв снимается.
3. Песочница Payme пройдена полностью: неверный ключ, неверная сумма, несуществующий заказ, оба сценария.
4. Выдача оплаченного заказа в `/staff` не просит взять деньги.
5. Возврат в кабинете Payme отменяет заказ.
6. Один настоящий платёж на малую сумму у каждого провайдера, затем возврат.
7. Сумма за день сходится в `/staff` и в кабинетах.
