# BOLAKAY DIRECT — сайт и система заказов через сеть холодильников

Мобильный сайт (узбекский / русский / английский, светлая и тёмная тема), заказ по QR-коду холодильника, резерв товара по партиям,
выдача по 4-значному коду, панель персонала и администратора.

**Стек:** Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · Supabase (PostgreSQL, Auth, Storage, pg_cron) · хостинг Render (или Vercel).

---

## Что уже работает (этап 1, MVP)

| Для покупателя | Для персонала (`/staff`) |
|---|---|
| Главная, «О ферме», список точек | Вход по email/паролю, роли: админ / оператор / курьер |
| Витрина точки `/point/<код>` — только товары в наличии | **Выдача**: поиск заказа, проверка кода, отметка оплаты (наличные/терминал) |
| Партии: «сегодняшнее / вчерашнее», дата производства, срок годности | **Остатки**: партии, резерв, «истекает», изъятие и списание |
| Корзина, выбор дня и интервала, оформление заказа | **Приёмка** партии: срок продажи считается автоматически |
| Код получения, статус заказа (обновляется сам), отмена | **Маршрут**: остаток / резерв / предзаказы / что забрать по каждой точке |
| «Мои заказы» на устройстве | **Температура**: журнал, подсветка вне +2…+6 °C |
| Предзаказ на отсутствующий товар | **Админ**: товары с фото, точки и QR-коды (PNG), отчёты, настройки, сотрудники |

**Гарантии на уровне базы данных** (функции PostgreSQL, обойти из браузера нельзя):
- одну единицу нельзя продать двоим (строки партий блокируются при резерве);
- нельзя выдать просроченную партию и выдать заказ без верного кода (проверка в `issue_order`);
- интервал получения должен закончиться до конца срока продажи партии, резерв не держится дольше этого срока;
- молоко третьего дня не показывается и не продаётся (`sell_days` у товара);
- неоплаченный резерв снимается автоматически (pg_cron каждую минуту);
- любое изменение остатка пишется в `stock_movements` (приёмка, резерв, снятие резерва, выдача, изъятие, списание);
- действия персонала пишутся в `audit_logs`; доступ к данным разграничен RLS.

## Запуск на компьютере

Нужен Node.js 20+ (установлен 26).

```bash
cd C:\Projects\dosan\sites\bolakay-direct
npm install
npm run dev -- -p 3100
```

Откройте http://localhost:3100. Ссылка из QR-кода выглядит как http://localhost:3100/point/tinchlik-01.

Файл `.env.local` уже заполнен ключами проекта Supabase **bolakay-direct** (регион Frankfurt).
Шаблон переменных — в `.env.example`.

## Первый администратор (один раз)

1. Supabase → проект **bolakay-direct** → **Authentication → Users → Add user → Create new user**. Введите свой email и пароль, отметьте *Auto Confirm User*.
2. **SQL Editor** → выполните (подставьте свой email):
   ```sql
   insert into public.staff (user_id, full_name, role)
   select id, 'Ваше имя', 'admin' from auth.users where email = 'you@example.com';
   ```
3. Войдите на `/staff`. Остальных сотрудников создавайте так же (шаг 1), а роль назначайте в панели: **Настройки → Сотрудники**.

## Telegram-бот

Бот уже развёрнут как Supabase Edge Function `telegram-bot`. Ему не хватает только вашего токена.

**Что умеет бот**

| Покупатель | Администратор |
|---|---|
| Подключение по кнопке «Уведомления в Telegram» на странице заказа (с согласия покупателя) | Новые заказы в чат администратора (личный или группа) |
| Подтверждение: номер, состав, сумма, точка, **код получения** | Вопросы покупателей. Ответ через *Reply* уходит покупателю |
| Уведомления: выдан / отменён / истёк резерв | |
| «Пришла новая партия» — для тех, кто оставил предзаказ | |
| `/orders` — последние 5 заказов, «🔁 Повторить» (корзина собирается на сайте с проверкой остатков) | |
| `/support`, `/lang` (узбекский/русский), `/stop` | |

Покупатели без Telegram по-прежнему оформляют заказ на сайте и видят код на странице заказа.
Бот не может написать человеку первым, пока тот сам не нажмёт «Start».

**Подключение (≈5 минут, после публикации сайта)**

1. Telegram → **@BotFather** → `/newbot` → имя `BOLAKAY` → username, например `bolakay_direct_bot`. Скопируйте токен.
2. Supabase → проект **bolakay-direct** → **Edge Functions → Secrets** → **Add new secret**:
   имя `TELEGRAM_BOT_TOKEN`, значение — токен. Токен хранится только там; в коде и базе его нет.
3. Откройте `https://<ваш-домен>/staff` → **Настройки → Telegram-бот** → **Подключить бота**.
   Бот получит webhook и меню команд, а ссылки в сообщениях будут вести на адрес, с которого вы нажали кнопку.
4. Там же → **Получить код подключения** → **Подключить личный чат** или **Добавить бота в группу** сотрудников.

> Если нажать «Подключить бота» с `localhost`, бот будет работать, но ссылки придут текстом:
> Telegram не принимает кнопки, ведущие на localhost. После публикации нажмите кнопку ещё раз с боевого адреса.

**Как это устроено:** триггеры в базе (заказ создан / сменил статус, новая партия) через `pg_net` вызывают функцию
`telegram-bot/notify`. Запросы от Telegram и от базы проверяются секретом из закрытой схемы `private`.
Исходник функции: `supabase/functions/telegram-bot/index.ts`. Для нового проекта Supabase её можно развернуть командой
`supabase functions deploy telegram-bot --no-verify-jwt`.

## Бот для заказов (второй Telegram-бот)

Отдельный бот для покупателей: Edge Function `telegram-shop`. Первый бот остаётся как есть: уведомления для заказов с сайта и чат администратора.

**Что умеет:** кнопка Web App (открывает сайт внутри Telegram), заказ прямо в чате (точка → товар → корзина → время → бронь), телефон кнопкой Telegram или вручную, код получения, «Мои заказы», отмена, повтор, заявка «Сообщить о поступлении», поддержка, три языка.

**Подключение**

1. Telegram → **@BotFather** → `/newbot`. Скопируйте токен. Это должен быть новый бот, не первый.
2. Supabase → **Edge Functions → Secrets** → секрет `TELEGRAM_SHOP_BOT_TOKEN` со значением токена.
3. Откройте `https://<ваш-домен>/staff` → **Настройки → Бот для заказов** → **Подключить бота**. Нужен адрес https: с localhost кнопки Web App не будет.

**Как это устроено**

- Заказ создаётся через `shop_create_order` → `create_order`: правила брони и остатков те же, что на сайте.
- В боте видны только заказы этого чата (`orders.tg_shop_chat_id`), а не все заказы с тем же номером телефона.
- Заказ с сайта внутри Web App привязывается к чату через `telegram-shop/link`, подпись Telegram проверяется.
- Новые заказы приходят в чат администратора первого бота. Ответ через *Reply* уходит покупателю через нужного бота (метка `#s<чат>`).
- Ссылка с QR-кода сразу на витрину точки: `https://t.me/<бот>?start=p_tinchlik-01`.
- Оплата в чате: кнопки Payme и Click появляются сами, когда способ включён в **Настройки → Онлайн-оплата**.

Развёртывание для нового проекта: `supabase functions deploy telegram-shop --no-verify-jwt`.

## Публикация (Render)

Сайт работает на Render как обычный Node.js-сервер (`npm run build` → `npm start`). Настройки уже лежат в `render.yaml`.
База, cron и Telegram-бот работают в Supabase, поэтому «сон» бесплатного тарифа на них не влияет.

**1. Код → GitHub (без командной строки)**
1. Установите **GitHub Desktop** (desktop.github.com) и войдите своим аккаунтом GitHub.
2. **File → Add local repository** → выберите `C:\Projects\dosan\sites\bolakay-direct` → на вопрос «create a repository» нажмите **create a repository** → **Create repository**.
   `node_modules`, `.next` и `.env.local` не попадут в репозиторий: их исключает `.gitignore`.
3. **Publish repository** → можно оставить **Keep this code private**.

**2. Render**
1. https://dashboard.render.com → **New → Blueprint** → подключите GitHub → выберите репозиторий `bolakay-direct`.
2. Render прочитает `render.yaml` и спросит две переменные:
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — скопируйте из `.env.local` (начинается с `sb_publishable_`);
   - `NEXT_PUBLIC_SITE_URL` — `https://bolakay-direct.onrender.com` (если имя занято, Render даст другое — тогда после деплоя поправьте значение в **Environment** и нажмите **Manual Deploy**).
3. **Apply**. Первая сборка занимает 3–6 минут. Адрес сайта — вверху страницы сервиса.
4. Supabase → **Authentication → URL Configuration** → **Site URL** = адрес сайта.
5. Каждый новый **Push origin** в GitHub Desktop пересобирает сайт автоматически.

**Бесплатный тариф:** через 15 минут без посетителей сервер засыпает, первое открытие после этого — 30–60 секунд.
Для запуска продаж переключите план на **Starter** (≈ $7/мес): Settings → Instance Type.

**Свой домен:** сервис → **Settings → Custom Domains** → добавьте `bolakay.uz` и `www.bolakay.uz` и создайте у регистратора
записи, которые покажет Render. SSL выпускается автоматически. После смены домена обновите `NEXT_PUBLIC_SITE_URL`,
Site URL в Supabase и нажмите **Подключить бота** в `/staff` ещё раз с нового адреса.

## Публикация (Vercel, альтернатива)

1. Загрузите папку `bolakay-direct` в новый репозиторий GitHub.
2. https://vercel.com → **Add New → Project** → выберите репозиторий → Framework: Next.js (определится сам).
3. **Environment Variables** — добавьте три переменные из `.env.example`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   - `NEXT_PUBLIC_SITE_URL` = боевой адрес, например `https://bolakay.uz`
4. **Deploy**.
5. Supabase → **Authentication → URL Configuration** → Site URL = боевой адрес.

### Домен и SSL
Vercel → Project → **Settings → Domains** → добавьте `bolakay.uz` и `www.bolakay.uz`. У регистратора домена создайте записи, которые покажет Vercel (обычно `A @ 76.76.21.21` и `CNAME www cname.vercel-dns.com`). SSL-сертификат Vercel выпустит сам.

> **Важно:** печатайте QR-коды только после того, как `NEXT_PUBLIC_SITE_URL` указывает на окончательный домен. QR скачивается в **Точки и QR**.

## Восстановление пароля сотрудников

На `/staff` под формой входа — «Забыли пароль?». Сотрудник вводит email → Supabase присылает письмо со ссылкой →
ссылка открывает `/staff`, где задаётся новый пароль (не меньше 8 символов). Ссылка действует 1 час и срабатывает один раз.

**Настройка в Supabase (один раз):**
1. **Authentication → URL Configuration**
   - Site URL = боевой адрес, например `https://bolakay-direct.onrender.com`
   - Redirect URLs → добавьте `https://bolakay-direct.onrender.com/staff` и `http://localhost:3100/staff`
   (без этого ссылка из письма поведёт на Site URL, а не в панель).
2. **Свой почтовый сервер (обязательно для реальной работы).** Встроенная почта Supabase отправляет письма
   только адресам участников вашей команды Supabase и не больше нескольких писем в час.
   **Authentication → Emails → SMTP Settings → Enable custom SMTP**, например бесплатный Brevo
   (smtp-relay.brevo.com, порт 587; логин и SMTP-ключ — в кабинете Brevo → SMTP & API; адрес отправителя
   нужно подтвердить письмом в Brevo). После этого в **Authentication → Rate Limits** можно поднять лимит писем в час.
3. **Текст письма** (по желанию): **Authentication → Emails → Templates → Reset Password**, например:
   - Тема: `BOLAKAY: смена пароля / Parolni tiklash`
   - Текст: `<p>Для смены пароля нажмите: <a href="{{ .ConfirmationURL }}">задать новый пароль</a>. Ссылка действует 1 час.</p><p>Parolni almashtirish uchun: <a href="{{ .ConfirmationURL }}">yangi parol</a>.</p><p>Если вы не запрашивали смену пароля — просто проигнорируйте письмо.</p>`

Самостоятельной регистрации сотрудников нет намеренно: аккаунты создаёт администратор (см. «Первый администратор»).

## Языки и тема

- Сайт: `/uz`, `/ru`, `/en`. Язык выбирается по cookie или языку браузера; переключатель O‘z / Ру / En в шапке.
- Панель `/staff`: свой переключатель O‘z / Ру / En (запоминается на устройстве). Переводы — `src/components/staff/i18n.tsx`.
- Тёмная тема: по умолчанию как в системе телефона, кнопка солнце/луна в шапке сайта и панели. Цвета — токены в `src/app/globals.css` (блок «ТЁМНАЯ ТЕМА»).
- Telegram-бот по-прежнему пишет на узбекском и русском.
Чтобы развернуть базу в новом проекте Supabase, выполните файлы по порядку в SQL Editor.

Основные таблицы: `products`, `fridges`, `batches` (партии), `stock_movements`, `customers`, `orders`, `order_items`,
`payments`, `preorders`, `temperature_logs`, `staff`, `audit_logs`, `settings`.
